# أدوات الفحص الأدبي للقراءة فقط

نقطة الأساس: `2ae1e9147064fb8fc0961233c905fe7ad043b516`.

## الاستخدام

من محادثة المساعد، والنص مفتوح في المحرر:
- «راجع استمرارية الشخصيات» — سجل حقائق مسند باقتباسات وملاحظات الاتساق.
- «حلل الإيقاع» — ملاحظات الإيقاع والعاطفة، مع مقاييس نصية تقريبية محسوبة محلياً.
- «اكشف ثغرات الحبكة» — مراجعة السببية والزمن والمكان، لا حكم قطعي على نية الكاتبة.
- «راجع الصوت الأدبي» — مقارنة أسلوبية داخل العينة؛ لا يدّعي معرفة بصمة الكاتبة من أعمال غير مرفقة.
- «تحقق من دقة هذه المعلومة التاريخية: …» — بحث Google مع المقاطع التي تدعمها بيانات الاستشهاد الفعلية للمزوّد.

يمكن ذكر فقرة عبر نظام الإشارات الموجود، أو طلب الحكاية كاملة. عند غموض الفصل أو عدم وجود نص يعرض الفحص خطأ توضيحياً، ولا يخمّن النطاق.

## مسار التنفيذ

`DarAlHikayatAIAssistant` → `executeAgentPlan` → `executeAnalysisPlan` → `analyzeLiteraryTool` → نقل Gemini المباشر أو مسار الخادم الموجود.

الأدوات الأربع الأولى تطلب JSON من النموذج، ثم تتحقق من الاقتباسات حرفياً داخل الفقرات المحددة. التحقق التاريخي لا يرسل المخطوط إلى البحث؛ يرسل السؤال فقط، ويستعمل groundingMetadata لتحديد المقاطع والمصادر. من دون دعم مرجعي صالح لا يسجل نجاح تحقق موثق. تعرض اقتراحات Google في iframe معزول بلا scripts أو same-origin.

هذا المسار لا يستدعي commit أو undo أو استبدال DOM أو أقفال التعديل. إذا تغير النص أثناء الانتظار تُرفض النتيجة القديمة دون استرجاع النص. يُلغى الطلب عند تغيير الحكاية أو المحادثة أو إزالة المكوّن. التقارير تحفظ عبر تخزين المحادثات الموجود، والخطوات المنقطعة عند استعادة التاريخ لا تظهر كفحص ما زال يعمل.

## الحدود والتكلفة

- خمسة استدعاءات كحد أقصى للدفعة؛ لا خلط بين تحليل وتعديل في دفعة واحدة.
- حد النص 120,000 حرف، وحد سؤال البحث 2,000 حرف، وحد طلب التركيز 4,000 حرف. تجاوزها ينتج خطأ واضحاً وليس قصاً صامتاً.
- مهلة الطلب 100 ثانية وحد المخرجات 6,000 token.
- يتطلب التشغيل مفتاح Gemini صالحاً وإمكانات النموذج المطلوبة؛ بحث Google قد يستهلك حصة/تكلفة إضافية.
- صحة الاقتباس لا تثبت صحة الحكم الأدبي. ربط مصادر Google ليس تدقيقاً مستقلاً للحقيقة التاريخية.
- لم يجر اختبار دقة نموذج حي أو بحث حي بمفتاح مستخدم، ولا اختبار هاتف فعلي أو دورة حياة Android/SQLite.

## الاختبارات المنفذة قبل النشر

- 413 اختباراً في 50 ملفاً: 372 اختباراً موجوداً و41 اختباراً جديداً.
- TypeScript وproduction build ناجحان؛ توجد تحذيرات حجم حزم من البناء.
- فحص عقد يحفظ نصّي التعليمات الأصليين byte-for-byte وتعريفات الأدوات التسع القديمة.
- اختبارات النطاق، الأدلة الملفقة، فشل الخدمة، الإلغاء، تعديل النص أثناء الانتظار، التاريخ المنقطع، وحماية مفاتيح الأدوات القديمة من أخطاء حصة البحث الخاصة.
- Chromium حقيقي بواجهة لمس 390×844: تشغيل الأدوات الخمس، حفظ خمسة تقارير، بقاء HTML الأصلي، صفر commits، وعدم تنفيذ script داخل إطار اقتراحات البحث.
- Express وGoogle SDK الحقيقيان: عقد البحث وبيانات الاستشهاد، واستمرار function calling القديم.
- ردود المزوّد في اختبارات المتصفح وSDK محاكاة مضبوطة؛ ليست طلبات Google حية.

إعادة الاختبارات: `npx vitest run` و`npx tsc --noEmit` و`npm run build`. فحص المتصفح الاختياري في `tools/literary-analysis-check/` يحتاج Playwright مثبتاً خارج اعتماديات التطبيق، وخادم Vite محلياً، ويمكن ضبط `QA_URL` و`QA_EVIDENCE`.

## خارج النطاق

لم تتغير ملفات الرسم أو Android أو الاعتماديات أو lockfile. كشف فحص الاعتماديات الحالي تنبيهات موجودة في html2pdf.js وjspdf وuuid، ومنها تنبيه critical في jsPDF؛ لم تعالج هنا لأن هذه الدفعة محصورة في الأدوات الخمس. نجاح الاختبارات لا يعني خلو التطبيق كله من الثغرات.
